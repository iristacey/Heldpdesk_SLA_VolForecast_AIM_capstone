# Generated output (canonical artifact root)

**In summary:** this folder holds the project's analysis tables, charts and reports under `issue_helpdesk/`. All active presentation deliverables, including the poster and both decks, are together in the root [`presentations/`](../presentations/README.md) folder.

`output/` is the canonical location for analysis and report artifacts.
Presentation files live in `presentations/`, and the persisted model lives in
`models/`. Nothing under `output/` is a raw input. See `docs/process_flow.md`
for the full step-by-step pipeline that produces this content.

## Active capstone (issues.csv)

- `issue_helpdesk/` — all Notebook 01-08 artifacts for the current capstone:
  `dataset_manifest.json`, `data_dictionary.csv`, `raw_column_profile.csv`,
  `source_quality_summary.csv`, `daily_coverage_audit.csv`,
  `sla_attainment_by_priority.csv`, `resolution_duration_audit.csv`,
  EDA/feature-selection/PCA tables, fairness/dashboard/monitoring/ROI
  artifacts, `capstone_completion_review.md` (hand-authored rubric
  self-review, preserved across regenerations), and:
  - `issue_helpdesk/volume_forecast/` — the shared 7-/30-day rolling-origin
    forecast backtest: predictions, metrics, model-selection and experiment
    metadata (`volume_forecast_experiment.json`).
    Supplemental `coverage_sensitivity/` contains causal missing-date
    scenarios and common-target scores; `ets_diagnostics/` contains the
    primary model's components, residuals and separate held-out errors.
    These do not replace canonical selection or metrics.
  - `issue_helpdesk/powerbi/` — a ready to use Power BI export folder for
    both the after the fact SLA report and the volume forecast:
    `fact_tickets_sla.csv` (ticket level SLA fact table), `dim_priority.csv`,
    `sla_summary_by_priority.csv`, `fact_daily_ticket_volume.csv`,
    `fact_volume_forecast.csv`, `model_comparison_metrics.csv`, and
    `power_bi_dashboard_spec.json` (pages, relationships and refresh
    instructions), all rebuilt by `run_powerbi_export()` in Notebook 06 from
    the current source data, so it scales to a larger dataset without any
    code changes.
    - `issue_helpdesk/powerbi/screenshots/` — one rendered sample image per
      report page listed in `power_bi_dashboard_spec.json` (SLA attainment,
      daily volume and forecast, model comparison, data contract and
      caveats), generated by `src/generate_powerbi_screenshots.py` from the
      tables in the same folder. Power BI Desktop is not installed in this
      environment, so these are rendered stand ins for native `.pbix`
      screenshots, not literal captures, and they refresh alongside the rest
      of the export folder.
  - `issue_helpdesk/reports/` — the consolidated written deliverable:
    `final_capstone_report.md` (authored source, hand-maintained like
    `capstone_completion_review.md`) plus its `.docx` and `.pdf` exports,
    regenerated by `src/generate_final_report.py` (see
    `docs/process_flow.md` step 13).

`src/generate_capstone_decks.py::build_all` writes both decks to the root
`presentations/` folder. `presentations/generate_presentation.py` writes the
packaged technical copy, daily-volume chart/data and forecast metadata there.
`src/generate_poster.py` writes the poster PNG/PDF there as well.

Regenerate everything here with (from the repository root):

```powershell
python presentations\run_volume_forecast.py
python -m src.generate_coverage_sensitivity
python -m src.generate_ets_diagnostics
python presentations\generate_presentation.py
python src\generate_poster.py
```

or by running notebooks 01-08 in order (each calls the corresponding
`src/issues_capstone.py` function — see `docs/process_flow.md`).

## Data-rights caveat

No file under `output/` contains a redistribution of the raw `data/raw/issues.csv`
source; only aggregated/derived statistics, model artifacts and reports are
written here. Source identity now matches the official Mendeley v2 digest/size and
downloaded Kaggle v1 bytes (see `data/source_verification.json`).
Mendeley's CC BY 4.0 must not be replaced by the conflicting Kaggle CC0
label without established authority. Review privacy and third-party
rights before publishing derived outputs; daily completeness is still
unverified.
